# 小游戏探索测试手册（通用模板）

> 用途：新游戏第一次接触时，用 AI 做一轮结构化探索，产出「探索记录 + 候选冒烟用例」。
> 复制本文件到 `docs/explorations/<游戏名>-探索大纲.md` 后按游戏增删。

## 红线（每次探索前确认）

1. **绝不完成真实支付**：测试号不绑支付方式 / 零余额；支付项只允许「拉起收银台 → 断言 → 取消」。
2. 每项探索结束**回到主菜单/重置状态**，避免状态污染下一项。
3. 探索结论必须**人工复核**，AI 只负责走查和记录，不做正确性判定。
4. 断网类探索项**仅在 USB 连接 adb 时执行**（无线 adb 会被飞行模式切断）。

## 使用步骤

1. 复制本文件 → `docs/explorations/<游戏名>-探索大纲.md`；
2. 把探索项落成 `games/<渠道>/<游戏>/explore/<游戏>-explore.yaml`（一个 case = 一个探索项，开头用 `recordToReport` 标注项名）；
3. 跑探索：`pnpm explore`（即 `midscene-test --project explore`）；
4. 把结论填进 `docs/explorations/<游戏名>-探索记录-<日期>.md`（模板：`探索记录-模板.md`）；
5. 从记录中挑核心场景，沉淀为 `games/<渠道>/<游戏>/smoke/*.yaml`。

## 探索项清单（8 项）

| # | 探索项 | 动作要点 | 观察/记录什么 | 测试理论 |
|---|--------|----------|---------------|----------|
| A | 进入与加载 | 冷启动 → 进入游戏；中间可能有健康忠告/Logo 页 | 加载时长、有无白屏/黑屏/卡死、协议弹窗 | 启动路径 |
| B | 主界面入口遍历 | 主菜单每个按钮/图标逐一点开→记录→关闭 | 入口是否齐全、打开后界面名称与内容、能否关闭 | 功能覆盖 |
| C | 商城/礼包 | 打开商城，记录全部商品（名称/价格/类型），逐个点详情（不购买） | 商品列表完整性、价格展示、详情页内容 | 等价类（商品类型） |
| D | 支付链路 | 选**未购买**档位 → 拉起收银台 → 记录金额/按钮 → **取消** | 收银台能否拉起、金额是否正确、取消链路 | 关键路径 |
| E | 存档持久性 | 进一局/领奖励 → 杀宿主 → 等 60s → 重进 | 「继续游戏」是否仍在、进度是否保留 | 状态持久化 |
| F | 玩法稳定性 | 进前几关随意操作 1~2 分钟（不要求通关） | 有无崩溃/黑屏/无响应/点不动 | 稳定性 |
| G | 断网与恢复 | 飞行模式开 → 观察游戏表现 → 恢复 → 观察恢复 | 断网提示、重连提示、恢复后能否继续 | 异常场景 |
| H | 弹窗与权限 | 检查公告/活动/更新/权限弹窗 | 是否可关闭、是否阻塞主流程 | 异常处理 |

## UI 视觉走查（内建在每一项末尾）

每个探索项结束前都会执行一次 `aiQuery`，让模型按固定维度输出「可疑点清单」。定位说明：

- **启发式判断**：模型只报告它「确实看到且能描述」的问题，**误报/漏报都正常**，结论必须人工复核；
- 输出直接进 HTML 报告，按探索项可回溯；记录模板里有「UI 视觉可疑点汇总」一节用于归纳；
- 若某个问题反复出现且可稳定复现，可作为候选冒烟断言（如「主菜单的 XX 按钮完整可见」）。

| 维度 | 查什么 |
|------|--------|
| 文字 | 截断、溢出、重叠、错别字、乱码/方块字 |
| 布局 | 错位、不对齐、间距异常、元素被遮挡 |
| 素材 | 裂图、占位图、图片缺失、模糊 |
| 控件状态 | 异常置灰、按钮不可见、点击区域过小 |
| 适配 | 刘海/圆角/手势区遮挡内容 |
| 内容 | 异常数值、错误文案、大片空白 |

## 沉淀规则

- 探索 YAML（`games/<渠道>/<游戏>/explore/`）**永不并入**冒烟集；
- 候选冒烟用例 = 探索记录中被人工确认「核心且稳定」的场景，转 YAML 后连跑 2~3 轮全绿再保留；
- 人工补充的重要用例直接进 `games/<渠道>/<游戏>/smoke/`，与 AI 沉淀的用例同等对待；
- 每次版本迭代后，探索记录可作为「该游戏已知功能面」的参考基线。
